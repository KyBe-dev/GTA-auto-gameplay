# GTA Auto Gameplay

> **开发状态：Developer Preview（开发者预览）**
>
> M0 技术验收已经完成；M1-A 窗口发现与明确选择边界已完成实现和自动化验证，交互式收口验收仍待完成。项目现在处于 M1 Windows 平台能力开发阶段，但尚未实现真实游戏窗口捕获、真实输入控制、GTA 自动操作、面向普通用户的安装版本或经过验证的完整任务能力。

GTA Auto Gameplay 是一个实验性的 Windows 桌面软件项目。它计划通过捕获指定游戏窗口、识别画面与任务状态、选择可验证的语义动作，并模拟普通键盘鼠标输入，辅助完成受支持的 GTA 离线故事模式任务。

当前开发与验证基于 **GTA V Windows 离线故事模式**。项目会通过游戏适配器接口隔离 GTA 专属界面和任务逻辑；在 GTA VI Windows 版正式发布并经过实际测试前，不创建 GTA VI 工程或占位参数，也不声称支持或兼容 GTA VI。

## 当前状态

项目目前处于 **Developer Preview：M1 Windows 平台能力开发阶段**：

- M0 技术验收已经完成：已建立 .NET 10 LTS 解决方案、可构建的 WPF 空壳、无 Windows API 依赖的核心项目、Windows 平台边界项目和核心单元测试项目。
- 已建立首版 `GameMode`、`Evidence`、`GameState`、多帧 `StateEstimator`、`ControlSafetyState`、锁存式安全协调器，以及 Provider、凭据、输入和游戏适配器接口；这些是已完成的 M0 核心能力，不包含真实平台或云端实现。
- 已建立字段白名单内存日志、安全默认配置和独立仓库检查工具；仓库检查在本地和 GitHub Actions 中执行 Release 构建、全部测试、候选文件及完整可达 Git 历史扫描。
- M1-A 已完成实现和自动化验证：WPF 界面可以只读发现可见顶层窗口，并且只在终端用户明确操作后创建短期、仅内存的窗口选择；独立受控测试窗口用于人工验收。交互式收口验收仍待完成，且尚未实现窗口捕获、持续身份复核、前台输入资格验证、`SendInput` 或 GTA 自动操作。
- 当前没有经过验证的完整任务自动通关能力。
- GitHub 仓库中的源码压缩包不是普通用户安装包，也不会自动创建桌面快捷方式。

现阶段仓库将从 M1-B 开始继续逐步实现和审查 Windows 平台能力，并保持默认拒绝和公开仓库安全边界。详细切片见 [`docs/M1_PLAN.md`](docs/M1_PLAN.md)。

## 计划中的工作方式

软件计划形成以下闭环：

1. 只捕获用户选定的游戏窗口。
2. 使用本地视觉识别、OCR 和多帧证据估计当前游戏状态。
3. 确认当前任务阶段、可见目标、控制模式和状态置信度。
4. 选择语义动作，例如移动、互动、打开暂停菜单或查看地图。
5. 根据玩家实际键位映射，通过正常 Windows 用户态接口发送键盘鼠标输入。
6. 再次观察画面，验证动作是否成功；无法安全判断时暂停或交还控制权。

详细设计见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 项目范围

计划支持：

- GTA V Windows 离线故事模式的受支持任务。
- 指定游戏窗口捕获与本地画面识别。
- `Gameplay`、`Paused`、`Map`、`Menu`、`Cutscene`、`Loading`、`Failed` 和 `Unknown` 顶层状态区分；`Settings` 是 `Menu` 的子状态。
- 玩家可调键位的扫描、确认、手动录入和语义动作映射。
- 必要时安全地暂停游戏、检查地图并恢复原状态。
- 任务阶段跟踪、失败检测、重新同步和有限次数的安全恢复。
- 用户随时紧急停止，以及窗口失焦时自动释放本软件输入账本中仍处于按下状态的输入。
- 可选的 BYOK 云端低频辅助和无云端情况下的本地基本功能。

## 明确不支持

- GTA Online、多人模式或联网对战环境。
- 注入游戏进程、读取或修改游戏内存、内核驱动、反作弊绕过或 DRM 绕过。
- 通过修改游戏文件或使用未授权接口获得游戏内部状态。
- 在后台窗口、非目标窗口或状态不可信时继续发送输入。
- 内置共享 API Key、由项目维护者支付的公共 AI 额度或默认公共 API 中转服务。
- 未经验证就声称支持 GTA VI、所有任务、所有分辨率或所有语言。

## AI、BYOK 与费用

实时控制不会把每一帧发送给云端。窗口捕获、基础识别、状态融合、输入控制和安全停止优先在本地完成。

云端 AI 只计划作为低频后备功能，并采用 **BYOK（Bring Your Own Key）**：

- 每位终端用户自行申请、拥有并配置自己的 Provider API Key。
- 调用消耗该终端用户自己的 Provider 额度，不消耗项目维护者的额度。
- 项目不会在源代码、安装包或默认配置中提供共享 Key。
- 未配置 Key、额度耗尽、限流、超时或断网时，软件退回本地模式；本地无法安全判断时停止自动控制。
- 云端分析默认关闭，只有用户主动启用后才可上传游戏窗口的必要裁剪区域，不上传整个桌面。
- 免费额度可能变化，不构成项目对可用性或长期免费的保证。

用户凭据计划通过 Windows Credential Manager 或 DPAPI 的用户范围加密存储保存，不得写入日志、截图、崩溃报告或 Git 历史。

## 技术方向

- C#、.NET 10 LTS、WPF
- Windows Graphics Capture
- Win32 `SendInput`
- OpenCvSharp
- ONNX Runtime / WinML
- SQLite
- Windows Credential Manager / DPAPI
- Inno Setup（后续安装程序候选）

技术选型仍可能在实际基准测试、许可证审查和 Windows 兼容性验证后调整。

M1 中所有 HWND、`IntPtr`、`nint`、WinRT 和 Windows API 类型只能存在于 `GtaAutoGameplay.Platform.Windows`；Core 只接收不可变、平台中立的身份快照和结果。M1 只允许捕获终端用户明确选择的单个窗口，不使用整桌面捕获作为失败回退。

## 开发路线概览

- **M0（技术验收已完成）**：仓库、安全骨架、接口、日志、配置、StateEstimator 与紧急停止。
- **M1（进行中；M1-A 已实现，交互式收口待完成）**：游戏窗口发现与明确选择、所选窗口捕获、基础状态识别和受控测试窗口的最小输入闭环。
- **M2**：显示校准、键位扫描和地图菜单控制。
- **M3–M4**：任务观察、进度跟踪与基础导航。
- **M5–M6**：单个任务端到端验证与技能扩展。
- **M7**：BYOK Provider、凭据保护、缓存、限流与本地降级。
- **M8**：多任务覆盖和未来 GTA VI 适配准备。
- **M9**：许可证、隐私、安装程序、快捷方式和 GitHub Releases 发布检查。

完整里程碑和验收边界见架构文档。

M0 只建立架构、`GameState`/`Evidence` 领域模型、安全协调器、接口和可使用假对象运行的测试。真实窗口选择、Windows Graphics Capture、前台 HWND 验证和 `SendInput` 实现属于 M1。M0 不接入具体 Provider SDK、不保存真实凭据，也不创建 GTA VI 工程或占位参数。

M1 必须按以下顺序分片验收，不得合并实现：M1-A“窗口发现与明确选择边界”→ M1-B“窗口与进程身份重新验证”→ M1-C“Windows Graphics Capture 会话”→ M1-D“最基础本地状态观察”→ M1-E“前台目标和输入资格验证”→ M1-F“真实输入控制器的最小安全实现”→ M1-G“最小闭环集成”。M1-E 通过前真实输入调用必须始终为零；M1-F/G 的真实输入也只允许发送到项目自建的独立受控测试窗口，不得向 GTA V 发送输入。

## 隐私与安全

- 只捕获终端用户明确选择的单个游戏窗口；不得自动选择 GTA 窗口，也不得根据 GTA 标题或进程名自动控制窗口。
- Capture Target 与 Input Target 必须分离并分别验证；捕获成功不等于具有输入资格。
- 软件以标准用户权限运行。目标权限更高或窗口/进程身份无法验证时拒绝操作，不自动提权。
- 自动控制状态应在界面中持续可见，用户输入和紧急停止可以立即接管。
- 失去窗口焦点、捕获失败或识别置信度不足时，只释放本软件输入账本中仍处于按下状态的输入并停止自动控制。
- 日志默认不保存画面，只记录经过字段白名单过滤的结构化事件，并受到容量和保留期限限制。截图、捕获帧和录像不默认保存；未来如提供相关功能，必须由终端用户明确启用并限制保留范围。
- 公开仓库不得包含 API Key、用户凭据、账户信息、游戏存档、游戏本体文件或未经授权分发的游戏素材。

### 仓库安全检查

提交或推送前应运行：

```powershell
dotnet run --project tools/GtaAutoGameplay.RepositoryGuard --configuration Release -- --repository . --history --allowlist tools/repository-guard.allowlist.json
```

该工具只读取已经跟踪和未被 `.gitignore` 排除的候选文件；`--history` 还会检查所有本地可达分支与标签中的历史文件。发现项只显示路径、规则 ID 和安全说明，不显示完整疑似秘密值。允许列表只接受精确规则与精确文件路径，不允许目录通配豁免。

这是项目自建的基础防线，不保证发现所有秘密，也不能替代成熟秘密扫描工具、GitHub Issue/PR/Actions/Release 托管内容检查或 M9 发布审计。完整规则和容量边界见 [`tools/GtaAutoGameplay.RepositoryGuard/README.md`](tools/GtaAutoGameplay.RepositoryGuard/README.md)。
